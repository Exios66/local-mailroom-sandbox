What the reports say

  1. Insurance claims is the most extractable type (0.67 local, 0.75 API). Correspondence is the hardest type with a valid score.
  2. Local AWQ matches the API on corporate records (0.42 vs 0.40) but reaches under half the API score on correspondence (0.23 vs 0.51).
  3. Contracts and merger have no valid local score. The Hub ground truth lacks the contract schema, and the merger leg ran the contracts prompt against MAUD labels. Their 0.0 reflects the measurement setup, not model quality.
  4. The API is cheaper per document on 4 of 5 types. Modal wins only on short correspondence ($0.0017 vs $0.0030), where it also finishes 16× faster.
  5. Qwen AWQ batches 6–7× at concurrency 8. Granite ran requests one at a time (1.0–1.4×) and cost 7.8× more on the merger leg.
  6. Correspondence scores rose 2.6–2.9× between 25 and 27 Sep, but the cause is confounded. The prompt text was identical. The scorer, the prompt-delivery path, the draw and the serving setup all changed between those runs.
  7. ModernBERT routes at 89.5% doc-type accuracy for 1/37 of the LLM sorter's latency. Its weak class is corporate records (57%).

What changed between 25 and 27 Sep

  • Scorer. Commit 8e507e1 (25 Sep, after c5/c8) stopped counting empty or other-class ground-truth fields as misses. Correspondence rows carry about 18 GT keys, most of them empty.
  • Prompt delivery. Before commit 6dbf457 (27 Sep), run-config prompt pins were not applied, so c5/c8 sent the vendored default text. Run A and Run B were the first to send the pinned local file.
  • Draw. c5/c8 drew 20 docs from train+test with no subclass quotas. Run A/B drew subclass-stratified docs from the test split.
  • Serving. 1×L4 with max_num_seqs 256 vs 2×L4 with 6.
  • Only one document appears in both eras (DOC-5c54a5baef4b9f06). It scored 0.0348 on c5 and 0.1276 on Run B.
  • Run-to-run stability on the same draw is ±0.02 (Run A vs Run B: 19 of 20 shared docs identical, mean |Δ| 0.0008).

Data quality

Every figure on this page is read from a tracked file and cross-checked

reports/dashboard/build_scorecard.py reads each value out of a report table cell, sentence or JSON key. It then checks each per-document table against its report's run-level mean, latency sum, p50, token totals and subclass means. A mismatch fails the build unless it is a documented issue listed here. The test suite runs the same check.

Data issues found in the tracked reports

    • The insurance serving export records a 428.98 s wall ($0.0954) from item timestamps; the run report and Modal archive record the 422.15 s busy interval ($0.0939). This page uses the report.
    • Serving exports and reports use two dataset fingerprints: the locked draw file's sha256 vs a hash of the row contents (job/metrics.py). Both identify the same draw.
    • API legs come from the sibling eval-environment repo as summarized in the Run B report. Their raw files are not tracked here.
    • TTFT is never inferred for local serving and is not shown.
