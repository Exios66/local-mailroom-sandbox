## [Unreleased]

- **New production slice preparations select the verified rc.10 label cut.** The seven slice configs, their assertion and operator instructions advance together after mailroom-issues #253 merged; the pinned source commit and manifest stay unchanged. All sixteen files verify and the rc.9 comparison preserves protected truth. Existing run locks keep their original selection. No run, deployment or stable release is launched.
- **Expanded label EDA and source-grounded corporate repair.** Notebook 05 inspects current interim/near-gold snapshots, optional pinned-corpus coverage, subclass applicability, runtime support and evidence. Four admissions add 71 missing corporate entity fields on 34 documents (69 populated facts, two absences); 16 fields remain held. A bounded source-type audit holds 244 officer-field assignments pending instrument adjudication rather than collecting generic fillers.
- **Corporate extraction composes dedicated runtime schemas for all eleven registered subclasses.** The native and LangChain specialists use observed sorter routing to select Dojo core/entity constraints, with fingerprint-bound sandbox hotfixes HF-020–HF-022. Missing subclass routing retains an explicit core-only fallback; unknown explicit subclasses are refused. Source-text label admission now accepts only applicable subclass targets and typed, evidenced entity values. The schema report checks the actual runtime fields instead of exempting corporate entities. New schema/helper identities participate in provenance; frozen locks and vendor snapshots stay unchanged. Follow-up: [llm-mailroom#322](https://github.com/Exios66/llm-mailroom/issues/322).
- **Phase 3 subclass extraction schemas (`job.subclass_schemas`, always on for pipeline runs).** Every pipeline extraction (all five classes) is sent its predicted subclass's schema from the committed `config/extraction/subclass_extraction_fields.json`, which `scripts/build_subclass_fields.py` derives from the label registry without held-out labels. Unset resolves on for `task: pipeline` and off elsewhere; an explicit `false` on a pipeline run is refused. Class fields the Dojo never scores as a value for the subclass (not applicable, absent from Dojo or documented absent), and that no dev, calibration or pool label gives a value, are dropped: contract `maud_clauses`/`merger_consideration`; merger `intent`/`keywords`/`subject_matter`; insurance `cms_source_table`, `adjuster`, `denial_reasons` where absent; corporate `filing_number` on four subclasses, plus `jurisdiction`/`signatories` on `subsidiary_list`. Labeled extension fields are added; today there are none. An unknown, `other` or unlisted subclass, or a class confidence below the `low` band, keeps the class schema. The file's sha256 is locked for pipeline runs; a run whose lock records a hotfix set from before HF-023 is refused on resume, and `--force` re-locks it with subclass schemas on. HF-023 applies the choice per specialist instance and leaves a corporate specialist whose `extract` another hotfix composes to that hotfix. HF-024 gives the judge, the arbiter and the retry summary the same fields: dropped fields are not listed as expected or shown. A missing, NaN or non-numeric confidence falls back to the class schema. An ad-hoc pipeline eval with no lock uses the committed field lists, and an added registry list field (`entity_list:*`) is requested as an array. The registry gains a per-field `valued_by_set` count. Plan: `docs/design/plans/2026-11-26-phase3-subclass-schemas.md`.
